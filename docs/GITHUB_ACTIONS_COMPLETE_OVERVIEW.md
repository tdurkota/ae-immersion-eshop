## Architecture Overview

### High-Level Flow

```
Developer Push → GitHub Actions Workflow → Build & Test → Deploy to Azure → E2E Validation
                                                ↓              ↓                    ↓
                                         .NET/Docker      Container Apps    Playwright Tests
                                         (Local Build)    (Managed Service)  (Staging Env)
```

| **Testing** | Playwright | ^1.62.1 | End-to-end browser automation |
| **CI/CD Platform** | GitHub Actions | ubuntu-latest | Workflow orchestration |
| **Databases** | PostgreSQL + Vector | Latest | Primary data store |
| **Cache** | Redis | Latest | Session/cache layer |

## Jobs & Pipeline Stages

### 1. **Build & Test Job**

**Name:** `build-and-test`  
**Runs On:** ubuntu-latest  
**Permissions:** read-only (contents, packages)

#### Steps

| # | Step | Purpose | Command |
|---|------|---------|---------|
| 1 | Checkout code | Clone repository | `actions/checkout@v4` (fetch-depth: 0) |
| 2 | Setup .NET | Install .NET runtime | `actions/setup-dotnet@v4` with 10.0.x |
| 3 | Restore dependencies | Download NuGet packages | `dotnet restore eShop.Web.slnf` |
| 4 | Build solution | Compile .NET projects | `dotnet build eShop.Web.slnf --configuration Release --no-restore` |

#### Output
- ✅ Compiled binaries (artifacts/bin/)
- ✅ Ready for deployment

#### Notes
- Unit and functional tests are **commented out (Phase 2)**
- Test results upload disabled pending Phase 2 implementation
- Security scanning disabled pending Phase 2 implementation

### 2. **Deploy to Staging Job**

**Name:** `deploy-staging`  
**Runs On:** ubuntu-latest  
**Needs:** `build-and-test` (must complete successfully)  
**Environment:** `staging` (GitHub Environment protection)  
**Permissions:** read-only (contents)

#### Job Outputs
```yaml
outputs:
  staging-url: ${{ steps.get-staging-url.outputs.url }}
```
This output is consumed by the `e2e-tests` job to dynamically discover the deployed endpoint.

#### Steps

| # | Step | Purpose | Notes |
|---|------|---------|-------|
| 1 | Checkout code | Clone repository | `actions/checkout@v4` |
| 2 | Setup .NET | Install .NET runtime | Required for Aspire CLI |
| 3 | Install Aspire CLI | Install deployment tool | `dotnet tool install -g Aspire.Cli --version 13.5.3` |
| 4 | Azure Login | Authenticate to Azure | Uses `secrets.AZURE_CREDENTIALS` (service principal) |
| 5 | Deploy to Azure | Deploy services | `aspire deploy --non-interactive --from-module` |
| 6 | Get Staging URL | Discover webapp FQDN | Query Azure for auto-generated URL |

#### Deployment Process Details

**Command:**
```bash
aspire deploy --non-interactive --from-module ${{ secrets.ASPIRE_MODULE_PATH }}
```

**Environment Variables (Passed to Aspire):**
```bash
Azure__SubscriptionId: ${{ secrets.AZURE_SUBSCRIPTION_ID }}
Azure__ResourceGroup: ${{ secrets.AZURE_RESOURCE_GROUP }}
Azure__Location: ${{ secrets.AZURE_LOCATION }}
ASPIRE_ALLOW_UNSECURED_TRANSPORT: "true"  # CI environment uses HTTP
```

**What Aspire Deploy Does:**
1. Parses AppHost resource graph from `Program.cs`
2. Creates container images for each service
3. Pushes images to Azure Container Registry (auto-created with auto-generated name)
4. Provisions Azure resources:
   - Container Apps (for each service)
   - PostgreSQL server and databases
   - Redis cache
   - RabbitMQ queue
   - Virtual networks & security rules
5. Configures service-to-service communication
6. Sets up health checks and restart policies

**Get Staging URL Step (NEW):**
```bash
WEBAPP_URL=$(az containerapp show \
  --name webapp \
  --resource-group ${{ secrets.AZURE_RESOURCE_GROUP }} \
  --query properties.configuration.ingress.fqdn -o tsv)

# Validation
if [ -z "$WEBAPP_URL" ]; then
  echo "ERROR: Failed to retrieve webapp FQDN"
  exit 1
fi

echo "url=https://$WEBAPP_URL" >> $GITHUB_OUTPUT
```

**Why This Matters:**
- Aspire auto-generates resource names (e.g., `webapp.wonderfulpebble-f244975f.westeurope.azurecontainerapps.io`)
- Previous hardcoded URL (`https://eshop-staging.azurecontainerapps.io/`) was dead
- Dynamic discovery ensures E2E tests target the actual deployed endpoint

### 3. **E2E Tests Job**

**Name:** `e2e-tests (Marketplace Flow)`  
**Runs On:** ubuntu-latest  
**Needs:** `deploy-staging` (waits for deployment to complete)  
**Consumes:** `staging-url` from previous job

#### Environment
```yaml
STAGING_URL: ${{ needs.deploy-staging.outputs.staging-url }}
```
Example: `https://webapp.wonderfulpebble-f244975f.westeurope.azurecontainerapps.io`

#### Steps

| # | Step | Purpose | Details |
|---|------|---------|---------|
| 1 | Checkout code | Clone repository | `actions/checkout@v4` |
| 2 | Setup Node.js | Install Node.js | Version 20, cached npm |
| 3 | **Install npm dependencies** | Install packages | `npm ci` (NEW - fixes "playwright not found" error) |
| 4 | Install Playwright dependencies | Browser binaries | `npx playwright install --with-deps` |
| 5 | Run E2E tests | Execute tests | `npm run test:e2e` (uses STAGING_URL) |
| 6 | Upload test results | Archive artifacts | `actions/upload-artifact@v4` (HTML reports) |

#### Test Configuration

**File:** `playwright.config.ts`

```typescript
const BASE_URL = process.env.PLAYWRIGHT_BASE_URL || 'http://localhost:5045';
// During CI in e2e-tests job:
// BASE_URL = https://webapp.{random-suffix}.{region}.azurecontainerapps.io

// Test settings
- fullyParallel: false              // Serial execution (shared basket state)
- retries: process.env.CI ? 2 : 0  // Retry 2x on CI, 0x locally
- workers: 1                        // Single worker (no parallelization)
- trace: 'on-first-retry'          // Debug info for failures
```

#### Test Suite

**Location:** `e2e/` directory

| Test File | Purpose | Flow |
|-----------|---------|------|
| `login.setup.ts` | Setup phase | Create authenticated user sessions |
| `BrowseItemTest.spec.ts` | Catalog browsing | View products, filters, search |
| `CartTest.spec.ts` | Shopping cart | Add/remove items, update quantities |
| `CheckoutTest.spec.ts` | Order placement | Checkout flow, payment (dependent on setup) |

**Dependencies:**
```yaml
setup        → login.setup.ts (creates user, generates auth cookies)
            ↓
e2e tests → CartTest.spec.ts (uses STORAGE_STATE)
         → CheckoutTest.spec.ts (uses STORAGE_STATE)
```

#### Package Scripts

```json
{
  "scripts": {
    "test:e2e": "playwright test",
    "test:e2e:headed": "playwright test --headed",
    "test:e2e:report": "playwright show-report"
  }
}
```

#### Artifacts
- **Output:** `test-results/` directory
- **Format:** HTML report + trace files
- **Retention:** Default (90 days)
- **Access:** GitHub Actions → Artifacts tab

## Deployment Process

### Local Development Flow (For Reference)

```
dotnet restore
↓
dotnet build --configuration Release
↓
aspire start  # Launches Docker containers locally
↓
Services accessible at http://localhost:XXXX
```

### CI/CD Deployment Flow

```
1. Build (.NET compilation)
   ├─ Restore NuGet packages
   ├─ Compile all projects
   └─ Create binaries

2. Authenticate (Azure)
   ├─ Use GitHub Secrets
   ├─ Establish service principal
   └─ Grant permissions

3. Deploy (Aspire)
   ├─ Read AppHost definition
   ├─ Build Docker images
   ├─ Push to ACR
   ├─ Provision infrastructure
   └─ Configure networking

4. Validate (URL Discovery)
   ├─ Query Azure for actual FQDN
   ├─ Verify deployment success
   └─ Pass URL to E2E tests

5. Test (Playwright)
   ├─ Authenticate against staging
   ├─ Run marketplace flows
   ├─ Capture results
   └─ Upload artifacts
```

### E2E Test Execution

**Trigger:** After successful deployment to staging  
**Environment:** Real Azure Container Apps instance  
**User Workflows Tested:**

1. **Authentication Setup**
   - Creates user account
   - Performs login
   - Captures auth cookies/tokens
   - Stores in `playwright/.auth/user.json`

2. **Product Discovery**
   - Browse catalog
   - Filter by category
   - Search functionality
   - Pagination

3. **Shopping Cart**
   - Add items to cart
   - Update quantities
   - Remove items
   - Persist across sessions

4. **Order Checkout**
   - Enter shipping address
   - Select payment method
   - Place order
   - Confirm order completion

### Test Isolation & Ordering

**Critical:** Tests run serially (no parallelization)
- Reason: Shared basket state in PostgreSQL
- Configuration: `workers: 1`
- Dependency tracking ensures setup runs first

### Retry Logic

| Scenario | Retry Count |
|----------|-------------|
| Local development | 0 |
| GitHub Actions CI | 2 |
| Failed step | Entire job re-runs |

### Test Result Reporting

- **Format:** HTML report + Playwright traces
- **Location:** `test-results/` directory
- **Access:** GitHub Actions Artifacts tab or local with `playwright show-report`
- **Contents:** Screenshots, video, detailed timings, errors

**File:** `src/eShop.AppHost/Program.cs`

#### Core Infrastructure

```csharp
// Databases
var postgres = builder.AddPostgres("postgres")
    .WithImage("ankane/pgvector")  // Vector DB for AI
    .WithLifetime(ContainerLifetime.Persistent);

var catalogDb = postgres.AddDatabase("catalogdb");
var identityDb = postgres.AddDatabase("identitydb");

    .WithLifetime(ContainerLifetime.Persistent);

// Message Queue
var rabbitMq = builder.AddRabbitMQ("eventbus")
    .WithLifetime(ContainerLifetime.Persistent);
```

#### Microservices

| Service | Dependencies | External? | Health Check |

| basket-api | redis, rabbitMq, identity-api | ❌ No | Default |
| ordering-api | orderDb, rabbitMq, identity-api | ❌ No | `/health` |
| order-processor | rabbitMq, orderDb, ordering-api | ❌ No | Default |
| payment-processor | rabbitMq | ❌ No | Default |
| webhooks-api | webhooksDb, rabbitMq, identity-api | ✅ Yes | Default |

#### API Gateways & Frontends

```csharp
// Mobile API Gateway (BFF Pattern)
```

## Error Handling & Validation

### Build Failures

| Scenario | Detection | Action |
|----------|-----------|--------|
| Compilation error | dotnet build fails | ❌ Workflow stops, developers notified |
| Missing dependencies | Restore fails | ❌ Workflow stops, update .csproj |
| Test failure | dotnet test fails | ❌ Blocked until Phase 2 tests enabled |

### Deployment Failures

| Scenario | Detection | Action |
|----------|-----------|--------|
| Azure auth fails | `azure/login` fails | ❌ Workflow stops, check secrets |
| Aspire deploy fails | Non-zero exit code | ❌ Workflow stops, review Aspire logs |
| Resource creation fails | ACR/ACA creation error | ❌ Workflow stops, check quotas/permissions |
| URL discovery fails | Empty FQDN or query error | ❌ Deploy step added validation (Phase 2 fix) |

### E2E Test Failures

| Scenario | Detection | Action |
|----------|-----------|--------|
| Network unreachable | Connection refused | ❌ Verify webapp is running (az containerapp show) |
| Auth timeout | 401 response | ❌ Check identity-api health |
| Test flake | Retries exhaust | ⚠️ Recorded in HTML report, manual review |
| Missing npm deps | "playwright: not found" | ❌ Fixed: Added `npm ci` step (Phase 2) |

### Validation Checkpoints

```
✓ Checkout complete
  ↓
✓ Dependencies resolved
  ↓
✓ Build succeeds
  ↓
✓ Azure credentials valid
  ↓
✓ Aspire deployment succeeds
  ↓
✓ Staging URL discovered (NEW - Phase 2)
  ↓
✓ npm dependencies installed (NEW - Phase 2)
  ↓
✓ E2E tests execute
  ↓
✓ Artifacts uploaded
```

## Troubleshooting Quick Reference

### "Playwright not found"
**Root Cause:** Missing `npm ci` step  
**Solution:** Ensure npm dependencies installed before playwright commands  
**Status:** ✅ Fixed in marketplace-cicd.yml (Phase 2)

### "Failed to retrieve webapp FQDN"
**Root Cause:** Aspire deployment didn't complete or webapp not running  
**Solution:** Check Azure portal, review aspire deploy logs  
**Prevention:** Added error handling in "Get Staging URL" step

### "STAGING_URL is empty"
**Root Cause:** Job output not passing between jobs  
**Solution:** Verify job outputs section and needs declaration  
**Prevention:** Validate job dependencies with `needs: [ deploy-staging ]`

### "Service Principal expired"
**Root Cause:** Outdated AZURE_CREDENTIALS  
**Solution:** Refresh service principal credentials, update secrets  
**Prevention:** Set calendar reminder for annual rotation

### E2E Tests Timeout on Staging
**Root Cause:** Network latency or resource under-provisioned  
**Solution:** Increase Container App CPU/memory, check availability  
**Prevention:** Monitor Container Apps metrics during deploy
